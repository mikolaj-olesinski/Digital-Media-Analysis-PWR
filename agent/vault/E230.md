# E230 · Out-of-platform transfer with more fields than likes + comments

## Question and hypothesis
- Question: does the transfer improve with more fields (shares, followers, all 8 export fields), with missing values imputed or columns dropped, and with CatBoost instead of ridge?
- Hypothesis: no consistent gain; field scales differ between platforms (E87, E162, E229).

## Setup
- A: leave one export platform out (train on the other two of TikTok / YouTube / X). Field sets: likes + comments; + shares; all 8 fields (followers, likes, comments, shares + 4 missing flags); only columns with < 20% missing on both sides (followers, likes). Ridge: missing reaction = 0 (as published), followers = training median; CatBoost: native NaN.
- B: Facebook from X + YT, + FB shares (re-read). C: Instagram from X + YT, + owner followers (E229).
- Paired brand-bootstrap diff vs ridge on likes + comments. `src/transfer_fields.py` (seconds, local).

## Results (factor; diff vs ridge likes + comments, CI)
- TikTok: base x2.05; + shares x2.21 (+0.033); 8 fields ridge x2.27 (+0.043), CatBoost x2.50 (+0.086); followers + likes x2.71 (+0.121). Every extra field hurts.
- YouTube: base x4.09; 8 fields ridge x3.88 (-0.023 [-0.035, -0.011]); followers + likes x3.90 (-0.021); CatBoost no gain.
- X: base x4.47; followers + likes (no comments) ridge x3.82 (-0.068 [-0.077, -0.058]); 8 fields worse (x4.89); CatBoost + shares x7.39.
- Facebook: base x2.43; + shares x2.44 (+0.002); CatBoost x2.67-2.97 (worse).
- Instagram: base x2.72; + followers ridge x4.58 (+0.227), CatBoost x2.66 (-0.009, CI includes 0); CatBoost likes + comments x2.92.

## Decision
Supported: no field set helps everywhere. Small gains only for YouTube (all fields, -0.02) and X (followers instead of comments, -0.07), losses on TikTok, no gain on FB / IG; CatBoost transfer is never clearly better than ridge. Likes + comments ridge stays the out-of-platform default.
