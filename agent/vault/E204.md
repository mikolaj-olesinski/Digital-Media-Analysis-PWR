# E204 · Full same-moment re-read of TikTok, YouTube and X

## Question and hypothesis
- Question: can we re-read views, likes and comments in one request for every TikTok/YouTube/X mention, so that the counters
  come from the same moment (as already done for Facebook)?
- Hypothesis: the export counts are stale but rank-stable; the fresh counts are usable as ground truth for transfer scoring.
- Refuted if: too many posts are unreadable, or the rank correlation collapses.

## Setup
- Input: every mention in the Brand24 export via `eda_utils.load()`; no raw file is edited.
- **YouTube:** `yt-dlp` (`view_count`, `like_count`, `comment_count`; shares do not exist), 1 req/s + jitter, resumable,
  `src/full_reread_youtube.py`, Kueue job `amc-ytfull4` (130 min). `source_field` is one spelling: `view_count`.
- **X:** FxTwitter free fallback (`views`, `likes`, `replies`, `retweets`), 1 req/s, `src/full_reread_x.py --free`.
  Checked against the paid API on 10 posts: 9/10 identical on all four fields (the only differences: one deleted post and
  one zero-view post where the paid API says 0 and FxTwitter null). One duplicate `mention_id` (2501 -> 2,500 rows, kept
  the latest `fetched_at`); the 24 remaining error rows were retried once and stayed error (deleted/unavailable).
- **TikTok:** **only 500 of the 2,500 posts**, read with a **logged-in headless browser** (exported cookies) via CDP on
  Xvfb, `playCount`/`diggCount`/`commentCount`/`shareCount`, 5-9 s per post, stop on captcha. An initial fast pass produced
  false "gone" rows and was repeated with a longer wait. The remaining 2,000 were **not** collected: whether a logged-in
  browser session is acceptable under the platform terms is a team decision that has not been made yet.
- Output (git-ignored): `data/processed/{youtube,x,tiktok}_full_fetched.csv` with
  `mention_id, platform, views, likes, comments, shares, fetched_at, status, source_field`
  (YouTube also `likes_hidden`, `comments_off`).
- Polite limits, resume, stop on blocks; no proxy/UA rotation/captcha solving.

### YouTube missing reactions
- 289 ok rows have no likes and 877 no comments; no zero is ever written for a missing value.
- A 10-row sample re-read with the public page shows: the like count is **visible on the page** where yt-dlp returned
  `None`, and comments are **not disabled** (`commentsDisabled` false) while `commentCount` is not present in the page
  data. The gap is therefore in **yt-dlp extraction**, not hidden likes and not turned-off comments.
- Columns added: `likes_hidden` and `comments_off`; `false` where the counter exists, **`unknown`** where it is missing
  (per-row cause not checked for all 1,166 rows, so no true/false is claimed).

### X duplicate
- 2,501 -> **2,500** rows (one `mention_id` had two error rows; kept the later `fetched_at`). Errors after the retry: 24.

## Decision
Same-moment counters are available for TikTok (first 500 only), YouTube and X (Facebook was E200), so the E93-style transfer
scoring can be re-run with a consistent timestamp. Use these files, not the export, as ground truth; the export stays for
features and the old counts. TikTok remains deliberately partial until the team decides on the logged-in-session question.
Not re-running the transfer models here: that is the next step after the counts are reviewed.
