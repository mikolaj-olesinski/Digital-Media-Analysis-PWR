# E204 · Full same-moment re-read of TikTok, YouTube and X

## Question and hypothesis
- Question: can we re-read views, likes and comments in one request for every TikTok/YouTube/X mention, so that the counters
  come from the same moment (as already done for Facebook)?
- Hypothesis: the export counts are stale but rank-stable; the fresh counts are usable as ground truth for transfer scoring.
- Refuted if: too many posts are unreadable, or the rank correlation collapses.

## Setup
- Input: every mention in the Brand24 export via `eda_utils.load()`; no raw file is edited.
- **YouTube:** `yt-dlp` (`view_count`, `like_count`, `comment_count`; shares do not exist), 1 req/s + jitter, resumable,
  `src/full_reread_youtube.py`, run in Kueue (`amc-ytfull4`, 130 min).
- **X:** FxTwitter free fallback (`views`, `likes`, `replies`, `retweets`), 1 req/s, `src/full_reread_x.py --free`.
  Checked against the paid API on 10 posts: 9/10 identical on all four fields (the only differences: one deleted post and
  one zero-view post where the paid API says 0 and FxTwitter null).
- **TikTok:** logged-in headless Chromium (cookies), `playCount`/`diggCount`/`commentCount`/`shareCount`, 5-9 s per post,
  stop on captcha; an initial fast pass produced false "gone" rows and was repeated with a longer wait.
- Output (git-ignored): `data/processed/{youtube,x,tiktok}_full_fetched.csv` with
  `mention_id, platform, views, likes, comments, shares, fetched_at, status, source_field`.
- Polite limits, resume, stop on blocks; no proxy/UA rotation/captcha solving.

## Result
| platform | rows | ok | gone | private | error | no_views | blocked | field |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| **TikTok** | 500 | **426** | 71 | 0 | 0 | 0 | 3 | `playCount` |
| **YouTube** | 2 500 | **2 297** | 93 | 37 | 73 | 0 | 0 | `yt-dlp view_count` |
| **X** | 2 500 | **2 013** | 438 | 0 | 24 | 25 | 0 | `fxtwitter.views` |

Fresh / export ratios (only rows with both values):

| platform | views median | views p90 | within 5% | Spearman | likes median / within5 / rho | comments median / within5 / rho |
|---|---|---|---|---|---|---|
| TikTok | **1.085** | 2.35 | 38.3% | **0.953** | 1.028 / 55.5% / 0.975 | 1.000 / 66.9% / 0.962 |
| YouTube | **1.350** | **20.68** | 23.2% | **0.856** | 1.077 / 44.9% / 0.919 | 1.000 / 56.5% / 0.893 |
| X | **2.000** | 6.02 | 6.2% | **0.905** | 1.000 / 47.3% / 0.893 | 1.000 / 74.9% / 0.850 |

- Median views: TikTok 782 -> 999, YouTube 463 -> 1,220, X 30 -> 60.
- The export is stale in **level** (X x2, YouTube x1.35, TikTok x1.09) but stable in **rank** (0.86-0.95).
- TikTok needed the slow path: at 2-3 s per post the page shows "Video currently unavailable" before loading; at 5-9 s the
  readable share went from 20/70 to 426/500.
- Cost: **$0** (YouTube/TikTok free; X via FxTwitter; the paid comparison cost $0.05).

## Decision
Same-moment counters are now available for TikTok, YouTube and X (Facebook was E200), so the E93-style transfer scoring can
be re-run on all five platforms with a consistent timestamp. Use these files, not the export, as ground truth; the export
stays for features and for the old counts. Not re-running the transfer models here: that is the next step after the counts
are reviewed.
