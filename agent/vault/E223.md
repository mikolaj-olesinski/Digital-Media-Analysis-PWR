# E223 · Can we find the FB / IG post owners on YouTube or X?

Data step only; no model is fitted here. The modelling question (does an account's audience profile on YouTube / X
predict how its FB / IG posts do) stays pre-registered and runs only if this step covers enough posts.

## Question and hypothesis
- Question: for the owners of the scored FB / IG posts, can we find the same account on YouTube and X from public pages,
  with evidence strong enough to trust (a bio link, or the same handle plus the same name plus a cross-link or badge)?
- Hypothesis (falsifiable): at least 40 scored FB / IG posts have an owner with a verified account on YouTube or X, and
  those accounts expose followers and recent per-post views / likes / comments.
- Refuted if: fewer than 40 scored posts are covered. Then the experiment is not worth running.

## Setup
- Owners: `author_url` in the export for the 402 scored FB videos and for the 696 scored IG reels. The public IG reel
  page is login-walled anonymously (checked: a 510 kB shell, no owner JSON, no og:description), so IG owners exist only
  where the export carries the handle.
- Matching: YouTube search by the owner's display name; up to two plausible channels opened on their `/about` tab;
  `bio_link` = the about section links to `facebook.com/<slug>` or `instagram.com/<handle>`; `same_handle_and_name` =
  identical handle and name plus a verification badge. A name alone is never a match.
- X: FxTwitter serves statuses only (its user endpoint answers 404, the public syndication timeline 429), so no public X
  profile lookup is possible without a logged-in session or the paid API. X is therefore reported as unavailable, not as
  zero matches.
- Politeness: one request per 4-6 s, one row written per owner, resumable; no proxies, no user-agent rotation.
- Output: `data/manual/cross_accounts.csv` keyed by a salted hash (salt in `data/manual/.salt`, never committed); counts
  only in `data/processed/cross_accounts_numbers.json`.
- Run: `.venv/bin/python src/e223_cross_accounts.py` (about 25 min for the 65 owners, local, not Kueue).

## Result
- 246 distinct owners behind the 1,098 scored posts: 181 Facebook (402 posts) and 65 Instagram (696 posts).
- Only the 65 IG owners carry a usable handle; **all 181 FB author URLs are numeric page ids** (`facebook.com/615…`),
  which no channel bio can be matched against. The verifiable scope is therefore 79 scored IG posts, not 1,098.
- YouTube: **11 of the 65 IG owners matched** (`bio_link` 11, `same_handle_and_name` 0), covering **17 scored IG posts**
  = 1.55% of the 1,098 scored posts.
- X: **0 matched, lookup unavailable** — no public profile source (FxTwitter profile endpoint 404, syndication 429).
- Gate: 17 < 40 scored posts covered -> not passed, so the experiment as specified is not worth running.
- The gate verdict is **provisional**: FB is 402 of the 1,098 posts and is excluded only because the export hides the page
  slug. The public `watch/?v=` page does expose the page URL in its owner block (verified on two posts), so slug recovery
  is feasible and is the next step if the team wants the FB half.

## Decision
Stop after the data step; do not run the E223 modelling on 17 posts. Two conclusions hold independently of the gate:
strong-evidence account matching works on Instagram (11 of 65 found, all by bio link, never by name), and the Brand24
export cannot supply FB owners that are checkable at all.

## Follow-ups
- Recover FB page slugs from the public watch page owner block (feasible, unverified at scale), then re-run this script
  with `--only-platform facebook`; coverage could grow with the 181 FB owners.
- X needs a team decision: the paid API token already on the machine, or a logged-in session — both are outside the
  "public pages only, no login" rule of this step.
- If coverage passes 40 after FB recovery, collect followers and the last 20 public posts per matched account (yt-dlp for
  YouTube, as in E204) before fitting anything.

## Independent second pass (2026-11-09)

A stricter, fully handle-based pass (`src/cross_accounts.py`) checked 247 owners (182 Facebook, 65 Instagram) with the same
public-only, strong-evidence rule: `youtube.com/@<handle>` and the FxTwitter user endpoint, accepting a match only when the
other profile links back to the owner's own platform URL.

- 5 of the 65 Instagram owners matched on YouTube (`bio_link`), 0 on X, 0 by `same_handle_and_name`; **5 scored IG posts**
  covered, so the 40-post gate still fails.
- All 182 Facebook "handles" are numeric page ids, so the `@handle` route cannot match them at all - consistent with the
  first pass, which excluded the Facebook half.
- The X user endpoint does answer with followers and a bio (the first pass reported it as 404); it still exposes no
  timeline, so the last 20 X posts remain uncollectable without the paid API or a login.
- Counts only: `data/processed/cross_accounts_numbers_deepseek.json`; the local per-owner file is git-ignored and keyed by
  a salted hash.
