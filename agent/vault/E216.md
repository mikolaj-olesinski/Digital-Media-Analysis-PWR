# E216 · Does a self-supervised representation (denoising autoencoder or SCARF) add signal?

## Question and hypothesis
- Question: does a representation learned without views, from all export rows plus the re-read rows, help the in-platform model or the transfer?
- Hypothesis (falsifiable): the primary variant (DAE, transductive) improves in-platform MAE by at least 0.01 (CatBoost on ENG + code vs ENG) or transfer MAE by at least 0.02 (ridge on C2 + code vs C2, X + YouTube -> FB / IG), with a paired CI above zero.
- Refuted if: gains are at or below these thresholds or the paired CIs include 0 on every platform.

## Setup
- torch 2.15 CPU (available in the `amc/runner:py314` image).
- Rich encoder inputs (in-platform): ENG + english + text_len + 16 e5 PCA components (`embeddings_e5_cache.pkl`), 26 inputs. Transfer encoder inputs: log likes + log comments + 16 e5 PCA, because that is all FB / IG reads have.
- Rows: all 12,500 export rows (views never used) + the re-read rows with their fresh likes / comments (other fields from the export row); transfer encoder also sees the FB 402 / IG 642 target rows' features (transductive).
- DAE: 20% swap noise, MSE reconstruction. SCARF: corruption rate 0.6 from the marginals, InfoNCE with tau = 0.5 and a small projection head. Encoder MLP 64-64 -> 8-dimensional code; 50 epochs, Adam 1e-3, batch 256, seed 42.
- Downstream: `rt.FINAL` on ENG (base) vs ENG + code, brand-grouped 5-fold CV per platform; ridge on C2 trained on export X + YouTube (base FB 0.385 / IG 0.435) vs C2 + code; re-read X + YouTube source as sensitivity. Reference: the same models on the raw inputs (ENG + english + text_len + e5 PCA; C2 + e5 PCA, cf. E100) to separate representation from inputs.
- Leakage: the transductive encoder sees all rows (no views); the strict variant refits the encoder (and PCA) inside each fold without the test-fold rows, and without any FB / IG rows for the transfer.
- Paired brand bootstrap (300 draws); all variants reported; target views never used for selection.
- Queue job: `amc-ssl`, 4 CPU / 4 GiB.

## Result
MAE of log10 views (factor x10^MAE), brand bootstrap CI; gain = MAE(base) - MAE(variant), paired brand bootstrap, + = better. Encoders fitted on 12,500 export + 3,815 re-read rows (+ 1,044 FB / IG target rows for the transductive transfer encoder). Job `amc-ssl-1108-215924`, 4 CPU / 4 GiB.

- Re-read X + YouTube source (sensitivity, 3,389 rows; base FB 0.387 / IG 0.382): codes change FB by -0.031 to +0.004 and IG by -0.013 to +0.004; no CI above zero.
- The single positive CI (SCARF transductive on IG, +0.042) is not the primary. It does not hold in the strict fit (-0.010) or with the re-read source (-0.005), and the same encoder costs FB 0.034. With 16 code-vs-base transfer comparisons, one such hit is what chance gives.
- The code does about as well as the raw inputs it is built from in-platform (X: raw +0.010 vs code +0.005). It does not add signal beyond them.

## Decision
Refuted: the primary DAE code gains at most 0.005 in-platform (CIs include 0) and is worse on the FB transfer (-0.027). This is consistent with E11 / E65 (little beyond reactions in-platform) and E100 (text-derived inputs hurt the FB transfer; a compressed code hurts less than raw e5 but still does not help). Self-supervised representations are closed for this data.
