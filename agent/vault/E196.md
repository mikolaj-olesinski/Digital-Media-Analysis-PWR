# E196 · Facebook re-fetch: do the public view counts move?

## Question and hypothesis
- Question: the Facebook sample was fetched on 2026-11-05; how much did `video_view_count` change in three days?
- Hypothesis: a small increase, as on TikTok/YouTube.
- Refuted if: the counts are identical (the public surface is cached or frozen).

## Setup
- 60 rows from `fb_all_fetched.csv` with views > 0, joined to the raw URLs; the public watch page re-read on 2026-11-08.
- Run: `python src/fb_refetch.py`.

## Result
| quantity | value |
|---|---|
| readable / attempted | **60 / 60** |
| median new/old views | **1.000** |
| p10 / p90 ratio | 1.000 / 1.000 |
| within 5% / within 20% | **1.00 / 1.00** |
| Spearman log views | 1.000 |
| median views | 493.5 -> 493.5 |

## Decision
Facebook's public `video_view_count` did **not move at all** in three days across 60 videos, unlike TikTok (+7% median) and
YouTube (+52%). Either the counter is updated rarely or the public watch page serves a cached value. Practical consequence:
for Facebook our sample is effectively frozen at the fetch date, so drift is not a source of error there - but the absolute
level may lag the true counter, which we cannot see. This supports treating the FB measurement as a single-time snapshot
(E93/E95) and not re-fetching it for freshness.
