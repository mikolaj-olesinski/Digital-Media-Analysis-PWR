# E236 · Other linear models than ridge on likes + comments

## Question and hypothesis
- Question: does another penalty or loss (no penalty, lasso, elastic net, Huber, median regression) beat ridge on log likes + log comments out of platform?
- Hypothesis: the penalty does not matter with two fields and thousands of rows; a robust (median-like) loss may help on X, where most posts have 0-1 likes.

## Setup
- Leave one export platform out (train on the other two) and FB / IG from X + YouTube, as in E230. Models on log likes + log comments, standardised: OLS, ridge alpha 1 (published), lasso alpha 0.01, elastic net alpha 0.01 (l1 0.5), Huber, median (quantile 0.5) regression. Typical error x10^MAE, paired brand-bootstrap difference vs ridge.
- `src/linear_penalties.py` (seconds, local). Earlier: E11 tuned the ridge alpha (about 51) for +0.001 MAE.

## Results (x10^MAE TT / YT / X / FB / IG; difference vs ridge, negative = better)
- OLS = ridge to the last digit (x2.05 / x4.09 / x4.47 / x2.43 / x2.72).
- Lasso and elastic net: x2.04-2.05 / x4.06 / x4.52-4.53 / x2.45 / x2.73-2.74; differences within +-0.006 MAE.
- Huber: x2.13 / x4.08 / **x3.98** / x2.47 / x2.85; X **-0.050** (CI -0.056 to -0.044), TT +0.016, IG +0.021, FB +0.006 (CI includes 0).
- Median regression: x2.14 / x4.07 / **x3.96** / x2.50 / x2.93; X **-0.052**, TT +0.017, IG +0.033, FB +0.013 (CI includes 0).

- In platform (nested brand-grouped CV, 8 fields, same protocol as the family table, `in_platform()`): ridge x1.89 / x3.51 / x3.07, lasso x1.89 / x3.50 / x3.07, elastic net x1.89 / x3.50 / x3.07 (TT / YT / X): no difference.

## Decision
Supported. The penalty and its form are irrelevant here (ridge = OLS; lasso / elastic net +-0.006). Robust losses help only on X (x4.47 to x3.96, still behind the multiplier x3.42 and ridge on likes + followers x3.82, E230) and hurt TikTok and Instagram. Ridge on likes + comments stays the default.
