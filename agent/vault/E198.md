# E198 · External X sample via the pay-per-use API (98 posts, $1.47)

## Question and hypothesis
- Question: can we fetch an independent X sample cheaply with the pay-per-use API, and does the X model hold on it?
- Hypothesis: a 7-day recent-search sample is small but usable; the model is close on the small posts that dominate it.
- Refuted if: the API returns too few posts with view counts, or the error is far above the export.

## Setup
- Bearer token in `.tools/x_token.txt` (git-ignored); app-only read.
- Recent search (last 7 days), 10 brands x 10 posts, `-is:retweet lang:en`, `public_metrics` + author followers.
- `impression_count` is the view count in the API; `reply_count` = comments, `retweet_count` = shares.
- Cost: **$1.47** for 98 posts (10 posts x $0.005 + users x $0.010), plus a $0.15 smoke test.
- Run: `python src/external_x.py --brands 10 --max-posts 100 --max-usd 2`; score: `python src/external_x_validate.py`.

## Result
| quantity | external X | Brand24 X |
|---|---|---|
| posts | **98** (87 with views > 0 and followers) | 1,803 |
| median views | **8** | 27 |
| model MAE | **0.565** | 0.454 (CV) |
| model bias | **-0.293** (over-predicts x2) | ~0 |
| median baseline MAE | 0.747 | - |
| cost | $1.47 | - |

## Decision
The API route works and is cheap: 98 posts for $1.47, so a 2,500-post sample would cost about $37.50, as estimated. But the
**7-day recent stream is dominated by very small posts** (median 8 views against 27 in the export), so the model
over-predicts them by about x2 (bias -0.29) while still beating the median baseline (0.565 vs 0.747). To make the X external
sample representative we need several weekly windows or a longer archive (Enterprise), not a bigger one-off budget.
